# چک‌لیست تست پذیرش — چرخه‌ی وضعیت سفارش

این پوشه سناریوهای Gherkin (قرکین) برای همه‌ی قابلیت‌هایی که روی چرخه‌ی وضعیت
سفارش ساختیم رو نگه می‌داره: کپشن‌های دقیق، پیگیری خرید تک‌به‌تک اقلام
خارجی، جست‌وجوی تگ، ثبت نتیجه‌ی نهایی، محاسبه‌ی هزینه‌ی باربری، و
برگشت‌خوردن ارسال (RTS).

## نحوه‌ی استفاده

هر فایل `.feature` یک حوزه‌ی مشخص رو پوشش می‌ده. هر سناریو یه شناسه‌ی یکتا
(تگ بالای سناریو، مثلاً `@TC-4.3`) داره تا هر وقت خواستیم یه مورد خاص رو
دوباره چک کنیم یا درباره‌ش صحبت کنیم، با همون شناسه ارجاع بدیم.

برای هر سناریو:
1. مراحل «با فرض» رو با ساختن داده‌ی تستی (یا از طریق UI یا با یه اسکریپت
   ساده که من می‌سازم) برقرار کن.
2. مرحله‌ی «وقتی» رو توی مرورگر انجام بده.
3. نتیجه رو با مرحله‌ی «آنگاه» مقایسه کن.
4. علامت ✅ یا ❌ بزن؛ اگه ❌ بود، شماره‌ی سناریو رو بگو تا بررسی کنم.

جایی که چندتا سناریو فقط توی چندتا مقدار پارامتر فرق داشتن (نه توی ساختار
تست)، به‌جای تکرار، از **«الگوی سناریو»** (Scenario Outline) + **«نمونه‌ها»**
(Examples) استفاده شده -- یعنی یه قالب تست، به‌همراه یه جدول از ترکیب
پارامترهایی که واقعاً توی کد قابل‌وقوعن (نه ضرب کارتزین کامل و کور همه‌ی
دیمنشن‌ها، که شامل حالت‌های غیرممکن هم می‌شد). هر ردیف جدول رو جدا چک بزن.
علامت «—» توی جدول یعنی «این پارامتر توی این ردیف بی‌ربطه».

بعضی سناریوها تگ `@known-gap` هم دارن -- یعنی موقع نوشتنشون یه رفتار فعلی
پیدا شد که دقیق/درست به‌نظر نمی‌رسه، ولی هنوز تصمیم نگرفتیم اصلاحش کنیم یا
نه. این‌ها رو جدا از باقی چک کن و نتیجه‌ش رو بگو تا تصمیم بگیریم.

## قرارداد

- کلمات کلیدی گرکین به فارسی: `ویژگی` (Feature)، `زمینه` (Background)،
  `سناریو` (Scenario)، `با فرض` (Given)، `وقتی` (When)، `آنگاه` (Then)، `و` (And).
- حساب‌های تستی: `admin@mudashop.ir` / `admin123` (ادمین)، `sara@example.com` /
  `customer123` (مشتری).
- هر سفارش تستی که برای یه سناریو ساخته می‌شه، بعد از چک‌کردن باید پاک بشه
  (طبق روال همیشگی این پروژه) — این کار رو من انجام می‌دم.
