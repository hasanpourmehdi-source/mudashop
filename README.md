# 🛍️ مُداشاپ (MudaShop) — فاز ۱ تا ۵ (کامل)

فروشگاه آنلاین پوشاک ایرانی با معماری **دو-منبعی**:
- **✦ موجود در مزون** — محصولات اختصاصی، ذخیره در دیتابیس، مدیریت از پنل ادمین
- **ترندیول** — کاتالوگ نمایشی از Fake Store API (فقط نمایش)

## چی ساخته شده

**فاز ۱:** احراز هویت (ایمیل/رمز + گوگل)، کاتالوگ دو-منبعی، سیستم variant ژنریک، فیلتر پیشرفته، سبد خرید per-user، پنل ادمین محافظت‌شده، Wishlist.

**فاز ۲:** آدرس‌ها، چک‌اوت واقعی با محاسبه مجدد سرور-ساید، کاهش موجودی اتمیک، سفارش‌ها + تایم‌لاین وضعیت، لغو سفارش با بازگردانی موجودی، پنل ادمین سفارش‌ها.

**فاز ۳:** کیف پول، کد تخفیف (۴ نوع)، حراج فلش با کش‌داون زنده.

**فاز ۴:** نظرات محصول (با برچسب خرید تأییدشده)، پرسش و پاسخ، جستجوی چندکلمه‌ای + autocomplete در هدر.

**فاز ۵ (جدید و پایانی نقشه راه اولیه):**
- **پرداخت کارت‌به‌کارت آفلاین (با تخصیص دستی ادمین)**: بعد از ثبت سفارش، موجودی/کوپن رزرو می‌شه ولی سفارش مستقیم وارد صفحه‌ی پرداخت نمی‌شه — اول می‌ره توی صف بررسی ادمین و همه‌ی ادمین‌ها اعلان (زنگوله) می‌گیرن
  - **هزینه ارسال دیگه خودکار حساب نمی‌شه** — ادمین موقع بررسی سفارش (بعد از محاسبه‌ی واقعی باربری) دستی وارد می‌کنه؛ برای کدهای تخفیف `FREE_SHIP` خودکار صفر در نظر گرفته می‌شه
  - ادمین از `/admin/orders/[id]` سفارش رو باز می‌کنه، هزینه ارسال رو وارد و از بین کارت‌های ثبت‌شده در `/admin/bank-cards` یکی رو انتخاب می‌کنه (یک فرم ترکیبی) — کیف‌پول (اگه مشتری موقع چک‌اوت خواسته بود) دقیقاً همین‌جا برای اولین‌بار اعمال می‌شه، چون مبلغ نهایی تا این لحظه معلوم نبود
  - اگه کیف پول کل مبلغ نهایی (شامل ارسال) رو پوشش بده، سفارش بدون نیاز به کارت فوراً `PAID` می‌شه؛ وگرنه مشتری اعلان می‌گیره و از `/payment/bank-transfer/[authority]` واریز می‌کنه و عکس فیش رو آپلود می‌کنه
  - بعد از آپلود فیش، سفارش به وضعیت «در انتظار تأیید فیش» می‌ره و ادمین‌ها دوباره اعلان می‌گیرن؛ از همون صفحه‌ی جزئیات سفارش می‌شه فیش رو دید و «تأیید» یا «رد» کرد
  - رد فیش = لغو کامل سفارش و بازگردانی خودکار همه‌ی منابع رزرو‌شده (موجودی variant، موجودی حراج، مصرف کوپن، کسر کیف پول) — دقیقاً مثل «انصراف از پرداخت»
- **پیگیری سفارش زنده**: صفحه سفارش هر ۸ ثانیه بدون رفرش صفحه خودش رو بروزرسانی می‌کنه؛ تاریخچه کامل هر تغییر وضعیت با زمان دقیق ثبت و نمایش داده می‌شه (`OrderStatusHistory`)
- **مدیریت کاربران** (`/admin/users`): تغییر نقش (مشتری/ادمین)، فعال/غیرفعال کردن حساب، و تغییر مستقیم رمز عبور توسط ادمین (بدون نیاز به رمز فعلی)؛ ادمین نمی‌تونه نقش/وضعیت حساب خودش رو از این پنل عوض کنه

با این فاز، تمام نقشه راه اولیه (فاز ۱ تا ۵) تکمیل شد.

## PWA (نصب روی موبایل/دسکتاپ)

مُداشاپ الان یک PWA کامله:
- `manifest.json` + آیکون‌های ۱۹۲/۵۱۲ (و نسخه maskable) در `public/icons/`
- Service Worker (`public/sw.js`): صفحات و فایل‌های استاتیک رو کش می‌کنه تا در حالت آفلاین هم چیزی نشون بده؛ مسیرهای `/api/*` و درخواست‌های غیر-GET همیشه مستقیم به شبکه می‌رن (داده سبد خرید/سفارش هیچ‌وقت کش نمی‌شه)
- صفحه آفلاین سفارشی (`public/offline.html`) وقتی هم شبکه و هم کش در دسترس نباشن
- بنر نصب سفارشی (`InstallPrompt`) که با رویداد `beforeinstallprompt` مرورگر فعال می‌شه

**نحوه تست:**
1. `npm run build && npm run start` (service worker روی `next dev` هم کار می‌کنه ولی برای تست واقعی نصب، build production بهتره)
2. تو Chrome: آیکون نصب کنار آدرس‌بار رو بزن، یا از DevTools → Application → Manifest چک کن
3. تو موبایل (Android/Chrome): منوی مرورگر → "Add to Home screen"
4. برای تست حالت آفلاین: DevTools → Network → Offline رو فعال کن و صفحه رو رفرش کن

نکته: روی هاست واقعی (نه localhost) باید حتماً HTTPS باشه وگرنه Service Worker ثبت نمی‌شه.

## Stack فنی

## نصب و اجرا (ویندوز)

> پیش‌نیاز: Node.js نسخه ۲۰ به بالا نصب باشه.

```bash
# 1. نصب پکیج‌ها
npm install

# 2. ساخت دیتابیس از روی schema
npx prisma generate
npx prisma db push

# 3. داده‌های اولیه (دسته‌بندی، کاربر ادمین، یک محصول نمونه با variant)
node prisma/seed.js

# 4. اجرا (روی پورت 3001)
npm run dev
```

بعد از seed:
- ادمین: `admin@mudashop.ir` / رمز `admin123` -> برو به `/admin`
- سایت: http://localhost:3001
- کدهای تخفیف نمونه: `WELCOME10` (۱۰٪ تخفیف، حداقل سفارش ۲۰۰,۰۰۰ تومان) و `FREESHIP` (ارسال رایگان)
- یک حراج فلش نمونه (۲۴ ساعته، ۳۰٪ تخفیف) روی محصول «پیراهن کتان کلاسیک» فعاله

## نکات مهم

- **پورت**: پروژه پیش‌فرض روی `3001` بالا میاد (`npm run dev` و `npm run start`). اگه `NEXTAUTH_URL` توی `.env` رو عوض کردی، باید دقیقاً با پورت واقعی یکی باشه وگرنه session/ورود silently خراب می‌شه.
- **کش Turbopack خراب شد؟** پوشه `.next` رو پاک کن و دوباره `npm run dev` بزن.
- **ورود با گوگل**: باید `GOOGLE_CLIENT_ID` و `GOOGLE_CLIENT_SECRET` رو توی `.env` پر کنی (از Google Cloud Console). بدون این‌ها فقط ورود ایمیل/رمز کار می‌کنه.
- **دیتابیس production**: توی `prisma/schema.prisma` مقدار `provider` رو به `"postgresql"` تغییر بده و `DATABASE_URL` رو به کانکشن‌استرینگ Postgres (مثلاً Neon) ست کن.
- محصولات ترندیول از `fakestoreapi.com` میان و قیمتشون (دلاری) با یه ضریب ثابت (در `src/lib/trendyol.ts`) به تومان تبدیل شده -- فقط برای نمایش دمو.
- **مهم:** پکیج `prisma`/`@prisma/client` عمداً روی نسخه ۶ پین شده (نه ۷). نسخه ۷ تغییرات breaking زیادی داره (نیاز به driver adapter، ESM، فایل config جدا) که با ستاپ ساده SQLite/ویندوز فعلی سازگار نیست. لطفاً این پکیج‌ها رو آپدیت نکن مگر با آگاهی کامل.

## ساختار پوشه‌ها

```
src/
  app/                 صفحات (App Router)
    products/mazon/[slug]     جزئیات محصول مزون
    products/trendyol/[id]    جزئیات محصول ترندیول
    admin/                    پنل ادمین (محافظت‌شده)
    api/                      API routes
  components/          کامپوننت‌های مشترک
  lib/                 پریزما، احراز هویت، منطق کاتالوگ دو-منبعی
  store/               Zustand (سبد خرید per-user)
  hooks/               useCart
prisma/
  schema.prisma        مدل کامل دیتابیس
  seed.js              اسکریپت seed (plain Node -- سازگار با ویندوز)
```
